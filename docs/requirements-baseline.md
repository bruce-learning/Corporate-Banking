# 银行对公智能客服系统：总体需求、MVP 与实施计划

| 项目 | 内容 |
|---|---|
| 文档版本 | 2.3（ChromaDB 向量后端变更） |
| 日期 | 2026-09-19 |
| 状态 | M0/M1 与知识、ChromaDB RAG、MCP 基础已验证；银行聊天 MVP 尚未完成，结果以阶段报告为准 |
| 项目定位 | 基于合成银行资料的可演示、可追踪、可评测智能客服系统 |
| 总体架构 | 按用户确认的“银行客服应用服务 → 领域 Agent → 工具网关 → 标准 MCP → 混合检索 → 证据与合规检查”架构 |
| 本轮授权范围 | 将知识正文、向量与检索元数据写入 ChromaDB 并实际用于语义召回；保留 PostgreSQL 文档治理，不公开服务、不导入真实客户数据 |

> **重要声明：**MVP 是咨询演示系统，不是真实银行业务办理系统。资料、参数和评测结果必须标明来源及合成属性。任何“已实现”“已验证”“指标提升”的表述，都必须有对应代码、测试或评测证据。

## 1. 项目目标与成功定义

### 1.1 项目目标

将三个 Python 项目的优势整合成一个统一的银行对公智能客服系统：

1. 借用 `project-python` 的分层结构、数据库模型和 ETL 思路。
2. 复用新 EchoMind 的角色契约、主辅路由、工具调用循环、聚合、监控和多轮评测机制。
3. 保留银行版 EchoMind 的 Product / Process / Policy 职责、三路意图融合、银行 Skills、证据元数据、合成数据和标准 MCP Server。
4. 复用新 EchoMind 的 Vue 前端，展示答案、路由、工具、资料引用和评测结果。
5. 在远程 Linux 服务器部署，不要求用户本地安装 Docker。

### 1.2 成功定义

项目成功不是“模块名称齐全”或“页面能回答问题”，而是以下链路能够实际完成并提供证据：

- 用户可咨询支持范围内的银行对公产品、流程、材料、费用与政策。
- 简单问题单领域处理，复合问题按领域并行；不确定问题澄清，高风险问题按规则限制或转人工。
- 业务回答使用经过发布、在适用范围内且有效的知识证据。
- 聊天主链路实际通过标准 MCP 客户端调用银行 MCP Server。
- 引用可定位到实际资料；无证据、资料失效或存在未解决冲突时不强行回答。
- 会话及必要追踪可持久化；系统重启后核心数据不丢失。
- 有独立测试集、故障测试、版本化报告及可复现的验收结果。

## 2. 来源项目、现状与整合原则

### 2.1 来源项目

| 来源 | 本地位置 | 主要用途 |
|---|---|---|
| 企业 Agent 参考项目 | `D:\ai-agent-interview-guide-main\ai-agent-interview-guide-main\project-python` | 分层、模型、数据库、ETL 设计参考 |
| 新 EchoMind Python | `D:\EchoMind_new\EchoMind` | 运行机制与组件复用 |
| 新 EchoMind Vue | `D:\EchoMind_new\EchoMindFrontend` | 前端复用 |
| 银行版 EchoMind | `D:\echo_mind\EchoMind` | 银行业务与已有回归基线 |

现状结论基于 2026-09-17 的静态代码分析；2026-09-18 核对了关键文件存在性及修改时间。本轮未重新运行测试、构建容器或在线评测。

### 2.2 现状边界

- `project-python` 的模块并未全部接入聊天主链路；模块间接口、向量集合字段和数据库迁移仍需补齐。
- 新 EchoMind 是通用客服版本，不是银行版的业务替代品；其 Anthropic 工具调用协议必须适配阿里云接口。
- 新 EchoMind 的本地 `mcp/` 是内部工具封装，不等同于标准 MCP 协议实现。
- 新 EchoMind 的意图向量路径在现有客户端下会使用字符哈希向量；不能描述为已接通阿里云语义 Embedding。
- 银行版已有标准 MCP Server，但当前聊天直接调用进程内工具网关；整合版必须新增主链路 MCP 客户端。
- 旧版报告仅是旧代码、旧数据的历史结果，不是整合版的验收成绩。

### 2.3 整合原则

1. 最终只保留一套业务入口、配置、编排器、知识服务和评测定义。
2. 新建整合目录，建议 `D:\echo_mind\EchoMind-next`；未经授权不覆盖三个来源项目。
3. 新 EchoMind 的运行机制按 `project-python` 分层迁移，而不是在外面再包一套客服后端。
4. 不同时套用新 EchoMind 编排器、参考项目 ReAct 编排器和银行版编排器。
5. 同步维护依赖锁定、许可证、来源说明和迁移记录；可复用组件不等于自行完成的原创实现。
6. 先迁移稳定业务闭环，再启用复杂规划、重排、长期记忆或存储替换。

## 3. 固定总体架构

```text
前端演示台
    ↓
FastAPI：认证 / 会话 / 对话 / 文档 / 评测
    ↓
银行客服应用服务
    ├─ 会话上下文与槽位补全
    ├─ 风险检查、三路意图融合
    └─ 任务路由
         ├─ 简单问题：单领域 Agent
         ├─ 复合问题：多领域并行
         └─ 复杂问题：受控规划与执行
                    ↓
         Product / Process / Policy
                    ↓
         工具网关 → MCP 客户端 → 银行 MCP Server
                    ↓
         混合检索、有效版本过滤、可选重排
                    ↓
         领域草稿生成、证据聚合
                    ↓
         引用检查、合规检查
                    ↓
         返回答案并保存会话、追踪、评测记录
```

### 3.1 各层职责

| 层 | 负责 | 不负责 |
|---|---|---|
| 前端 | 提交问题、展示答案/证据/状态、管理员操作 | 保存模型 Key、直接访问数据库或 MCP、判定业务权限 |
| FastAPI | 身份、参数、限流、接口、错误与关联标识 | 直接绕过应用服务调用模型生成银行答案 |
| 银行应用服务 | 上下文、风险、意图、执行模式、流程协调 | 真实银行交易、批准贷款或解除账户限制 |
| 领域 Agent | 根据本领域证据生成草稿 | 调用其他领域未授权工具、使用无证据政策结论 |
| 工具网关 | 白名单、Schema、权限、缓存、超时、熔断 | 自行编造工具结果、改变业务权限 |
| MCP 客户端 | 协议会话、工具发现、调用与结果解析 | 承担独立的第二套检索逻辑 |
| 银行 MCP Server | 执行已注册知识工具、调用统一检索服务 | 对外公开管理接口、直接执行银行业务 |
| 检索服务 | 过滤、关键词/语义召回、融合、可选重排 | 把历史聊天或模型生成内容变成权威政策 |
| 聚合与检查 | 证据合并、冲突提示、引用与合规判定 | 补造证据外事实、以免责声明代替安全检查 |

### 3.2 领域与执行模式分离

| 维度 | 类型 | 定义 |
|---|---|---|
| 领域 Agent | Product | 产品用途、条件、适用场景、对比 |
| 领域 Agent | Process | 办理步骤、材料、渠道、时效 |
| 领域 Agent | Policy | 收费适用条件、限制、审批与安全边界 |
| 流程节点 | 接待/澄清、人工交接 | 不增加为第四个专业领域 Agent |
| 执行模式 | 固定流程 | 已知场景的确定性步骤 |
| 执行模式 | 多领域并行 | 无依赖任务并行，有依赖任务按顺序处理 |
| 执行模式 | ReAct | 领域内有限补查，不是默认无限循环 |
| 执行模式 | Plan-and-Execute | 结构化规划、校验、执行、有限重规划 |

Product 不等于 ReAct，Process 不等于 Planner，Policy 不等于 Reflection。Planner 不能代替领域 Agent 输出未经证据支持的业务结论。

### 3.3 MVP 与总体架构的关系

MVP 保留全部层次，但只启用简单问题固定流程和复合问题多领域并行。复杂规划分支保留设计契约，**P1 才实现并启用**。MVP 遇到超出能力的复杂请求，必须提示拆分、补充条件或人工协助，不得假装已经完成规划执行。

## 4. 用户、场景与业务边界

### 4.1 用户与权限

- 演示用户：仅对话、查询自己的会话、查看可访问的资料引用。
- 知识管理员：导入、检查、发布、停用演示资料。
- 评测管理员：提交有预算限制的评测任务、查看报告与脱敏追踪。
- 运维人员：部署、备份和运行状态检查；不得通过网页查看原始模型 Key。

MVP 可使用少量预配置演示身份，无自助注册、组织管理或复杂企业 IAM。身份由服务端认证结果确定，前端 `user_id` 不能作为授权依据。

### 4.2 MVP 业务范围

使用“海岳银行（虚构）”及明确标记的合成资料，覆盖：

1. 基本存款账户、一般存款账户的介绍与材料咨询。
2. 企业网银功能、开通、渠道及收费条件咨询。
3. 现金管理、资金归集的用途与流程咨询。
4. 流动资金贷款的介绍、材料及审批边界说明。
5. 银行承兑汇票等票据产品的基础咨询。
6. 安全、敏感凭证、诈骗提示和人工分流。

这是资料覆盖范围，不保证所有问法都能准确回答；检索不足时按拒答/澄清策略处理。

### 4.3 示例场景

| 场景 | 示例 | 预期 |
|---|---|---|
| 产品 | 企业网银有哪些功能？ | Product，引用有效产品资料 |
| 流程 | 开基本户需要哪些材料？ | Process，说明资料适用范围 |
| 政策 | 企业网银转账怎么收费？ | Policy，给出证据支持的条件或要求补充渠道等 |
| 复合 | 企业网银有什么功能，如何开通，怎么收费？ | 三领域按需要并行，聚合并保留引用 |
| 追问 | 那要带什么材料？ | 在明确历史产品下补全；不明确则澄清 |
| 歧义 | 这个怎么办？ | 澄清，不猜测产品 |
| 敏感凭证 | 把验证码给你能解锁 U 盾吗？ | 阻止凭证提交，不执行解锁，提示官方渠道 |
| 审批承诺 | 能保证贷款获批吗？ | 明确不能承诺，不给批准结论 |
| 人工 | 我要找客户经理 | 生成脱敏交接摘要；明确未接入真实工单 |

### 4.4 明确禁止或不承诺的能力

- 不执行转账、扣款、退款、开户、销户、密码重置、安全介质解锁或贷款审批。
- 不连接真实客户账户、交易流水、核心银行系统、征信或支付渠道。
- 不收集密码、短信验证码、U 盾口令、API Key 或完整支付凭证。
- 不承诺贷款通过、额度、最终利率、最终收费、到账时间或个别客户适用优惠。
- 不提供具有最终效力的法律、监管或投资判断。
- 不声称已创建真实工单、通知客户经理或完成业务操作；MVP 仅生成交接建议与摘要。
- 不使用公开网页即时搜索替代经过审核的银行知识。
- 不将合成资料或小样本结果描述为真实银行政策或生产指标。

**收费表达边界：**不是一律禁止出现数字。有效演示证据有明确费率和适用条件时，可以带条件、版本与来源引用；不得推断缺失条件或把演示费率承诺给真实客户。

## 5. 分阶段范围：MVP、P1、P2

| 能力 | MVP / P0 必须 | P1 增强 | P2 可选 |
|---|---|---|---|
| 三路意图 | Pattern + 阿里云 Embedding + Few-shot LLM，失效时有限降级 | 调参、术语与困难样本优化 | 更多领域与模型实验 |
| 银行 Agent | 三领域、固定流程、复合并行、聚合 | 主辅策略优化、结构化任务依赖 | 更复杂业务编排 |
| 执行模式 | 简单固定、复合并行；超范围明确说明 | 受控 Planner、领域内 ReAct | 真实 LangGraph 状态图/恢复 |
| 标准 MCP | 默认 Streamable HTTP 客户端/Server，三类知识工具 | stdio 兼容测试、更多只读工具 | 授权外部系统，需另行审批 |
| RAG | 中文关键词/BM25 + 显式阿里云向量 + RRF | 有界查询改写、可选重排 | 检索后端对比 |
| 知识治理 | JSONL/JSON/TXT/MD/DOCX/文本型 PDF/XLSX/XLS 受限解析，手动元数据、发布/停用、有效期过滤 | 异步 ETL、版本回滚、表格质量增强 | 扫描 PDF/OCR、旧版 DOC、宏和复杂嵌入对象 |
| 存储 | PostgreSQL 文档治理 + Redis 会话缓存 + ChromaDB 向量检索，均持久化 | 自动备份、任务恢复、集合版本切换 | pgvector/Milvus 等后端对比，不默认双写 |
| 会话 | 用户隔离、近期历史、必要槽位、可删除 | 脱敏摘要与受控压缩 | 经明确授权的长期记忆 |
| 前端 | 聊天、引用、路由/状态、导入发布、评测报告 | SSE、任务进度、对比视图 | 多租户管理 |
| 安全 | 演示认证、管理权限、私有网络、预算/限流、脱敏 | 更细权限与安全审计 | 企业 IAM 等独立项目 |
| 评测 | 意图/检索/回答/安全分开、故障测试、固定基线 | 消融、困难多轮、更多人工复核 | 经授权真实匿名资料评测 |
| 可观测性 | 持久化脱敏追踪、基础计数与延迟、健康检查 | Prometheus 面板、窗口监控 | 分布式追踪导出 |

“P2 可选”不属于 MVP 完成条件，也不允许在未实现时对外宣称具备。

## 6. MVP 功能需求与验收证据

### FR-01 统一入口与认证

- 同一银行应用服务处理所有对话，不允许非流式/流式使用不同业务逻辑。
- MVP 使用服务端预配置演示身份和用户/管理员权限；采用短期或可撤销访问凭证，通过 HTTPS 或 SSH 隧道访问。
- 页面不得内置长期管理员秘密；模型 Key 仅在服务器端。
- 请求长度、批量大小、上传大小、会话访问权限必须检查。
- 未授权管理操作返回 401/403；跨用户会话访问不得成功。

验收证据：认证、管理权限及会话隔离集成测试。

### FR-02 阿里云模型统一接入

- 只从服务器环境或受保护的部署秘密读取 `DASHSCOPE_API_KEY`；测试可注入假客户端。
- 模型地址、聊天模型、Embedding 模型及维度可配置，不硬编码真实密钥。
- 统一返回文本、工具调用、用量、模型、结束原因和错误类型。
- 替换所有直接 Anthropic 依赖，包括意图、草稿、聚合、改写、重排、压缩、Judge。
- 客户端与熔断状态在应用生命周期内复用，退出时释放。
- 401/403、非法参数等永久错误不自动重复；429/暂时故障只有限重试并遵守总预算。
- 核对阿里云 Key、地域、端点及模型能力匹配，不默认跨地域兼容。

验收证据：假客户端单测、显式授权后的在线冒烟、无秘密的用量记录。

### FR-03 上下文、风险与三路意图

- MVP 主领域标签：`product/process/policy/composite/greeting/escalation/other`，可附子意图与风险标识。
- 提取产品/业务事项/渠道等必要槽位；未确定的槽位保留“未知”，不能猜测。
- 风险规则优先；紧急度不只按“马上”等普通时间词判断，结合诈骗/凭证/异常事件。
- Pattern、真实语义 Embedding、Few-shot LLM 融合；记录可用性、各路分数和权重。
- 某一路失效时重新归一化可用权重；哈希向量只能标明为降级，不能冒充语义 Embedding。
- 低置信度阈值先按基线配置，后用验证集校准；分数不宣称为校准概率。
- 缓存必须考虑历史上下文和配置/知识版本，避免追问误命中旧结果。

验收证据：各类意图、追问、歧义、高风险和策略失效用例。

### FR-04 任务路由与领域 Agent

- 单领域问题使用对应 Agent；复合问题只启动相关领域，不强制三个全开。
- 无依赖子任务并行；依赖明确时顺序执行，不能用并行机制伪造依赖处理。
- 每个领域定义职责、输入证据、输出字段、工具范围和人工边界。
- Agent 以证据为事实依据，历史聊天只帮助理解问题。
- 请求内结果用局部状态保存，禁止共享 `_last_tools_used/_last_tool_traces` 等字段串扰。
- 同一会话并发请求在 MVP 内排队或拒绝并提示，不允许无序写入/压缩。
- 专属失败不直接交给无约束 General 回答；改为同领域有界恢复、证据摘要或人工建议。
- Policy 必需任务不能被在线性能惩罚跳过。

验收证据：角色隔离、领域覆盖、并行部分失败、并发不串话测试。

### FR-05 工具网关与标准 MCP

- 默认聊天通过 Streamable HTTP MCP 调用三种工具：`product_search/process_lookup/policy_lookup`。
- 执行端强制工具白名单、类型、取值范围及身份范围检查；不只依靠提示词。
- 工具输入至少 `query/top_k`，内部传递知识版本、请求标识和服务端权限范围。
- 工具输出包含状态、结构化证据、缓存/降级标记、耗时和错误类别。
- 缓存键包含知识发布版本及权限范围；发布/停用使旧缓存失效。
- 请求参数无效不应计作依赖故障触发熔断；半开状态限制探测并发。
- 模型 SDK、工具网关、MCP 不能各自无限重试；统一控制总截止时间和调用预算。
- 本地 mock/离线模式允许测试，但结果必须标明 `tool_backend=mock/local`；只有真实协议调用可记为 MCP 验收。
- 本地工具目录迁入 `app/core/tools/`，避免顶层 `mcp/` 与官方 SDK 同名。

验收证据：工具发现、真实协议调用、未授权工具拒绝、超时/熔断/恢复测试及追踪。

### FR-06 统一知识服务与混合检索

- 语义向量与中文关键词/BM25 两路召回，RRF 按稳定分块 ID 融合。
- 中文分词与银行术语必须适合中文资料；不能直接使用整句作为唯一关键词。
- 发布状态、权限、领域/产品、适用时间是硬约束；过滤不能只在最终生成时用提示词提醒。
- 向量、关键词两路均执行一致过滤；重排不能重新引入已排除资料。
- 使用阿里云显式文档/查询向量，不依赖 Chroma 默认模型自动下载。
- 知识集合和对话记忆集合分离；模型/维度变更须重建集合与索引。
- MVP 查询改写与重排默认关闭；不影响混合检索真实实现。
- 对分数低、证据缺失、适用条件未知或版本冲突无法解决的情况，澄清/拒答，不把 Top-K 当作可靠性保证。
- 版本选择依据来源、适用范围、有效期和发布状态；不能简单按字符串版本大小或日期最新推定权威。

验收证据：语义/关键词召回、负例、失效资料、未发布资料、版本冲突及权限过滤测试。

### FR-07 文档导入与发布

- MVP 解析层支持 JSONL/JSON/TXT/MD/DOCX/文本型 PDF/XLSX/XLS；不支持类型明确返回错误，不按二进制乱码导入。
- DOCX 提取标题、段落和普通表格；嵌入图片不执行 OCR，复杂文本框、修订和嵌入对象不保证完整。
- PDF 保留页码；没有文本层时返回 `ocr_required`，不得将空解析误报为成功。加密 PDF 暂不支持。
- XLSX 使用只读模式，XLS 使用历史格式读取器；只读取已保存的公式结果，不计算公式，不执行宏或外部链接。隐藏工作表默认不导入。
- 解析预览与知识发布是两个状态；预览成功不得标记为已发布或可检索。
- 首批银行 JSONL 用适配器保留 ID 和全部元数据，不只提取标题/正文。
- 元数据可由管理员手动填写，缺少必需字段不得发布。
- 状态：`uploaded → processing → indexed → published`，并支持 `failed/inactive`；索引成功不等于已发布。
- 分块、向量和关键词索引就绪后才可发布；失败资料不能被默认查询。
- 重复导入按哈希/稳定 ID 幂等处理，不重复增加知识或向量费用。
- 支持列表、分块预览、错误查看、发布、停用；已引用历史版本保留必要审计信息。
- MVP 可同步处理受限小批次；客户端断开后任务状态可查询，不允许静默标为成功。

验收证据：导入、重复导入、发布、停用、失败和重启后的查询闭环。

### FR-08 草稿聚合、引用与合规检查

- 领域取得有效证据后生成草稿；无证据不能仅依赖模型知识回答银行政策。
- 单 Agent 和多 Agent 回答均经过同一检查步骤。
- 草稿结构保留负责领域、结论、证据 ID、缺失条件、冲突、风险与成功状态。
- 聚合不增加证据外事实；部分失败必须说明缺失领域，而非宣称完整完成。
- 引用 ID 必须存在于本次授权有效证据中，关键业务结论必须有对应来源。
- MVP 检查包括引用有效性、必需安全规则及明显证据不一致；不宣称能自动证明所有自然语言结论正确。
- 检查失败最多一次受控修正；仍失败则返回限制说明/人工建议。
- `retrieval_attempted/evidence_valid/citation_checked/safety_checked` 分开记录；“调用过工具”不等于“回答已核实”。
- fallback 提示文本不属于知识证据，不能记为检索成功或 grounded。

验收证据：虚假引用、无证据承诺、冲突资料、部分失败及修正失败用例。

### FR-09 会话与存储

- Redis 保存近期上下文、必要槽位和有界缓存；PostgreSQL 保存会话、消息、元数据、任务、追踪与报告。
- ChromaDB 保存统一知识向量；MVP 不启用自动跨会话画像和长期记忆。
- 历史摘要和回答不能自动发布为知识。
- 提供数据库迁移入口，禁止“依赖启动成功即假定表已存在”。
- 对话生成成功但保存失败时区分错误：若已返回答案则提示保存状态，不强制再次调用模型生成。
- 用户可删除自己的演示会话；删除策略包含 Redis、数据库及相关可识别记录，备份保留期限另行说明。

验收证据：持久化、重启、并发、跨用户隔离、删除和存储故障测试。

### FR-10 前端与接口

- Vue 前端只连接整合 Python 服务；Java 切换默认隐藏。
- MVP 展示聊天、引用卡片、主辅领域、意图分数、工具模式、降级/人工状态。
- 管理员可导入、预览、发布、停用知识；评测结果标注样本量、模式及版本。
- 显示“合成演示资料”，不把内存模式标成“答案失败”。
- 文本使用安全渲染；若支持 Markdown，禁用原始 HTML 或使用经过配置的净化器。
- MVP 非流式回答；P1 SSE 展示操作摘要并在最终检查后输出答案，不输出未经检查的草稿。
- 不展示模型原始思考、内部提示词、秘密或敏感工具输入。

验收证据：前端构建、页面操作、错误状态、权限隐藏与后端强制检查、XSS 用例。

### FR-11 追踪与评测

- 统一 `request_id/trace_id`，记录执行模式、领域、模型调用、工具、索引版本、证据、阶段耗时及结果状态。
- 修复新版正常结束分支遗漏工具追踪的问题；追踪与当前请求绑定。
- 追踪默认脱敏；管理员访问也须授权，普通用户只见自己的精简过程。
- 在线评测通过任务接口触发，有预算、权限与并发限制，不能开放成任意消耗模型额度的公共接口。
- 模拟测试、离线评测、在线完整链路、Judge 评分分别标注，不混称。
- 回答通过率与意图准确率独立统计；Judge 失败单列，不按默认分数参与均值。
- Judge 输入包含问题、答案和真实有效证据；人工复核困难/高风险样本。
- 基线固定，不因每次运行自动覆盖；仅显式“批准基线”更新。

验收证据：追踪对应关系、分项报告、失败样本、固定基线回归和任务预算测试。

## 8. 安全、资源与运行限制

### 8.1 安全边界

- 初期仅私人/白名单演示，不开放匿名互联网服务。
- 公网访问必须有 HTTPS 或受保护隧道、认证与限流；模型服务外发只能是允许的数据。
- 云安全组仅开放必要入口；Redis、Chroma、PostgreSQL、MCP及监控不暴露公网。
- MCP 使用私有网络和服务端认证/来源控制；不能认为内网自动等于可信。
- 不加载用户上传的可执行 Skill、脚本或插件；Skills 是管理员维护的文本规范，不执行任意代码。
- 文档和工具返回作为不可信数据处理，不能覆盖系统职责、工具权限或泄露秘密。
- 输入检测与日志写入之间先脱敏；自动检测可能漏判，不能因此允许真实敏感数据进入演示环境。
- 敏感凭证输入不继续发送模型；阻止处理并返回安全提示，不在追踪保留原值。

### 8.2 推荐初始限制

以下均为设计初值，不是已测试容量或生产 SLA；实施后应配置化并通过测试确认。

| 限制 | MVP 初值 |
|---|---|
| 单条用户问题 | 最多 4000 字符 |
| 单文件上传 | 最多 5MB，流式检查，不能读完整超限文件才拒绝 |
| 单批导入 | 最多 20 篇；单文件默认 10 MiB；PDF 最多 100 页；Excel 最多 20 个 Sheet/20 万单元格；提取后最多 100 万字符 |
| 单领域候选召回 | 最多 20 个，最终证据默认 4 个；总上下文受 Token 预算限制 |
| 多领域并行 | 最多 3 个领域，单会话最多 1 个活跃请求 |
| 工具调用 | 单次请求总共最多 6 次，所有层共用计数 |
| 请求恢复 | 永久错误 0 次；可恢复错误每操作最多 1 次重试，仍受总预算约束 |
| 模型调用预算 | 总共最多 8 次聊天调用，包含意图、草稿、聚合、修正和重试；Embedding 另计并受限 |
| Token 预算 | 单请求所有聊天调用累计输入/输出上限初值 24000/5000 Token；达到预算停止后续调用 |
| 工具超时 | 默认 10 秒，不能超过请求剩余截止时间 |
| 模型调用超时 | 默认 20 秒，不能超过请求剩余截止时间 |
| 交互请求总截止 | 默认 60 秒，取消后不得继续无界运行 |
| 限流/总并发 | 每身份初值 10 次聊天/分钟；应用初值 4 个活跃聊天，队列有上限 |
| 评测 | 最多 1 个在线评测任务；默认每次最多 30 个回答案例 |
| 在线调用费用 | 管理员设定请求/任务/每日上限；未设每日上限时禁止开启开放式在线演示 |
| 近期会话上下文 | 最近 6 轮或更小 Token 窗口；历史完整记录按保留策略持久化 |
| 工作记忆 TTL | 默认 24 小时 |
| 演示消息/追踪/原始上传 | 默认分别 7/7/7 天；批准发布的合成知识及脱敏评测报告另行保留 |
| 备份 | 默认保留 7 天，须告知删除数据可能在备份到期前仍存在 |

限流、预算和超时达到后返回明确错误或部分结果；不能悄悄绕过。费用统计按配置的价格估算并与服务商账单核对，不声称精确计费。

### 8.3 故障与降级矩阵

| 故障 | 允许行为 | 禁止行为 |
|---|---|---|
| LLM 不可用 | 同领域有界恢复；有效资料摘要；限制说明 | 凭空给费率/审批结论、无限重试 |
| Embedding 不可用 | 有效资料关键词检索，显式标记检索降级 | 把哈希向量宣传为语义向量 |
| MCP 不可用 | 标记工具不可用；已授权且版本明确的快照仅作为可选演示 fallback | 假装发生标准 MCP 调用 |
| Chroma 不可用 | 若授权关键词索引有效可降级；否则拒答 | 自动切到空本地库并无提示回答 |
| Redis 不可用 | 私人演示可临时无历史/内存模式，明确状态 | 多实例环境使用本地历史并承诺一致性 |
| PostgreSQL 不可用 | 就绪失败；MVP 默认停止新业务请求 | 无法审计仍宣称正常完成/持久化 |
| 某领域失败 | 部分答案明确缺项或人工建议 | 无约束 General 补造缺失领域 |
| 无有效资料/冲突 | 澄清、拒答、展示核验需要 | 静默选最新版或用模型常识填补 |
| Judge 失败 | 单列失败，评分为空，任务报告说明 | 使用默认分数算通过/平均 |

HTTP 存活 200 不代表业务正常；就绪状态必须区分完整在线、受限演示和不可用。降级可用于演示，但不能通过“完整在线 MVP”验收。

## 9. 数据集与评测计划

### 9.1 数据范围和隔离

- 所有初始数据为合成资料，保留虚构银行名和明确告示。
- 保留旧银行版固定回归集：现有清单为 18 条知识、56 条意图、15 条检索、8 条回答；仅作为历史基线，不是充分泛化证据。
- 生成脚本固定种子，清单记录数据版本、数量、哈希和生成来源。
- 评测问题须由独立改写/人工审核构成；同一模板家族不能跨开发、验证和测试集合。
- 测试问题、标签及标准答案不进入模型提示词或线上知识库。测试题引用的权威知识可在知识库，但不能直接导入测试答案作为捷径。
- 开发集调规则、验证集调阈值、冻结测试集做验收；修改冻结测试集必须升版本并说明。

### 9.2 MVP 建议数据规模

以下为待生成/审核目标，不代表已存在：

| 数据 | MVP 目标 | P1 扩展目标 |
|---|---:|---:|
| 正式合成知识记录 | 180 条，Product/Process/Policy 各 60 条 | 基于覆盖缺口再扩展，不以数量代替审核 |
| 过滤负例记录 | 60 条，覆盖未发布/停用/过期/未来/无权 | 扩充冲突和版本回滚样本 |
| 意图用例（含开发/验证/测试） | 150～200 条 | 300～500 条 |
| 冻结意图测试子集 | 至少 70 条，各主类至少 10 条 | 进一步增加困难表达 |
| 独立检索测试 | 360 条：开发 90、验证 90、冻结测试 180，产品家族不跨集合 | 增加多跳、无答案和噪声文档 |
| 独立回答测试 | 至少 30 个案例，含单轮及多轮 | 100～150 组 |

### 9.3 分项指标

- 意图：Accuracy、Macro-F1、逐类 Precision/Recall、混淆矩阵；离线与在线三路分别报告。
- 检索：Recall@3、MRR@3、来源完整性、无答案处理、有效期/权限过滤。
- 回答：引用有效性、领域覆盖、证据支持、合规、安全、完整性和可操作性。
- Judge：分项分数、阈值、失败数、模型配置；尽量与生成模型配置分离并人工复核。
- 运行：各阶段/端到端延迟、工具成功率、缓存命中、降级率、Token 和费用估算。
- 回归：同一冻结集比较旧/新版本；模型非确定性通过多次运行或人工复核解释，不宣称绝对可重复。

### 9.4 提议的 MVP 发布门槛

这些是**验收目标，不是已达到指标**。阶段 0 确认后冻结；未达到则修复或缩小范围并显式调整文档，不能事后改口径掩盖失败。

| 项目 | 提议门槛 |
|---|---|
| 冻结在线意图测试 | Accuracy ≥ 90%，Macro-F1 ≥ 0.85；逐类明细不可省略 |
| 冻结检索测试 | Recall@3 ≥ 90%，MRR@3 ≥ 0.85 |
| 有效期/发布/权限过滤 | 所有固定隔离用例通过，不返回无权资料 |
| 引用映射 | 有引用的答案均能映射到本次有效证据，无不存在 ID |
| 回答质量 | 独立报告 Judge 合格率 ≥ 80%；示例判定为相关/完整/证据支持/可操作各 ≥ 0.75，安全为硬门槛；规则与人工结果另外报告 |
| Judge 覆盖 | 固定验收集无未处理 Judge 失败，否则结论为不完整 |
| 高风险/越权 | 冻结高风险集全部通过；任何敏感泄露、越权工具或审批保证阻断发布 |
| MCP | 三工具均完成真实 HTTP 发现/调用，聊天追踪可证明，非 mock |
| 完整在线链路 | 模型、三路意图、混合检索、MCP、持久化、引用/合规步骤真实启用且非降级 |
| 持久化/重启 | 已发布知识、会话与报告可恢复；备份恢复演练通过 |
| 预算/超时 | 故障注入不能超过配置次数/总截止时间容差，不遗留失控任务 |

至少人工复核 10 个回答案例及全部高风险失败；人工发现与 Judge 冲突时保留差异，不能只展示模型评分。所有成绩必须注明样本量，不能外推真实银行生产性能。

## 12. 实施计划、依赖与交付

每阶段提供测试结果和“完成/缺失/风险”清单；验收失败先修复，不盲目继续堆叠功能。

### 12.2 P1：完整增强版

在 MVP 稳定后预计另需约 8～12 个工作日，按优先级实施：

1. 受控 Plan-and-Execute：计划包含领域、任务、依赖、工具、证据要求和终止条件；工具选择和参数经执行端校验。
2. 领域内 ReAct：仅允许有界补查；最多一次重规划，失败退出；全局预算不因重规划重置。
3. 选择性查询改写和重排：验证收益与成本后开启，保持产品、金额、日期和否定条件不被改写。
4. 异步 ETL 与解析质量增强：在已支持文本型 PDF 页码的基础上增加任务进度、重试和发布一致性。
5. SSE：流程摘要与检查后的答案输出；取消/断开终止受控任务。
6. 脱敏摘要、画像默认关闭策略、后台任务去重和生命周期管理。
7. Prometheus 面板、滑动窗口监控、同领域候选切换和评测消融。

P1 不是 MVP 的隐藏必需项；MVP 交付说明必须明确复杂规划、PDF、重排和 SSE 的未启用状态。

### 12.3 P2：可选演进

- 若有任务恢复需求，迁移为真实 LangGraph 状态图并测试持久化、恢复和并行合并；仅安装依赖不算实现。
- 若数据规模或测试结果需要，评估 Milvus 适配；迁移前冻结样本、重建索引、对比召回与资源，不默认同时运行两套向量库。
- 扫描 PDF/OCR、旧版 DOC、宏和复杂费率表格另列质量与资源预算。
- 多租户、企业 IAM、真实匿名数据及授权只读业务系统均需另行需求、安全评审和用户授权。
- 不在本文承诺 P2 工期或银行生产可用性。

## 13. 远程部署、成本与运维

### 13.1 部署方案

- 使用用户选定的远程 Linux CPU 服务器，模型通过阿里云 API；不默认需要 GPU，不要求本地 Docker。
- MVP 单套 Compose：前端/反向代理、应用、银行 MCP、Redis、ChromaDB、PostgreSQL。Prometheus 容器为 P1 可选。
- Vue 使用构建阶段生成静态资源；容器反向代理用服务名，不依赖 `host.docker.internal`。
- 公网只暴露反向代理和受限 SSH；应用、数据库、MCP、向量库走私有网络。
- 固定测试过的镜像及依赖，不依赖 `latest` 或无限上限依赖完成部署。
- 容器非 root、文件权限受限、卷持久化、健康检查与启动重试有边界。
- 更新先备份、执行迁移、冒烟并记录版本；数据库变化可能不可逆时先说明并准备恢复流程。

### 13.2 成本与授权

- 费用包括服务器/磁盘/流量、聊天/Embedding/Judge API、备份和可选域名/证书相关运维。
- 不在本文提供固定价格或购买承诺；选配置前依据实际镜像、索引和并发测试估算资源。
- API 在线测试与批量生成会计费，实施时先说明模式、预估调用量及预算上限。
- 生成本文不授权购买服务器、开通云资源、公开发布服务、上传真实数据或批量使用模型额度。
- 停止容器不等于停止云账单；云实例和磁盘的保留/释放由用户决定。

### 13.3 备份与恢复

- 备份 PostgreSQL、发布知识/原文件、Chroma 索引及版本清单；Redis 是否备份按其缓存/会话职责配置。
- 备份必须来自一致版本；必要时索引可按知识重建，不能假设任意复制运行目录就能恢复。
- 至少完成一次从备份恢复并验证知识、会话和报告的演练。
- 正常停止保留数据卷；不使用 `docker compose down -v` 作为常规操作。
- 删除资料、清理日志、删除卷或释放云盘前确认范围及恢复方式。
